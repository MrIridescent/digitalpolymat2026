# Search, discovery, and AI visibility

This is the operating playbook for making `mriridescent.africa` findable — in
Google and Bing, in AI answer engines, and in the human networks where the next
client or collaborator actually looks. It documents what the code already ships,
what only the owner can do (accounts, profiles, submissions), and how to measure
whether any of it works.

**Honest position:** technical SEO makes a site *eligible* to rank and *easy* to
cite. It cannot guarantee a position, a rich result, or an AI citation. The
durable advantages are a consistent identity, original work, and being present
where the conversation already happens.

## 1. What ships in the build

| Asset | URL | Generated by | Purpose |
| --- | --- | --- | --- |
| Sitemap | `/sitemap.xml` | `app/sitemap.ts` | Every static route plus Contentful posts |
| Robots | `/robots.txt` | `public/robots.txt` | Allows search and AI crawlers, blocks `/api/` |
| AI entry point | `/llms.txt` | `app/llms.txt/route.ts` | Compact, curated profile for answer engines |
| AI long form | `/llms-full.txt` | `app/llms-full.txt/route.ts` | Full record: services, credentials, projects, hubs, FAQs |
| RSS | `/feed.xml` | `app/feed.xml/route.ts` | Journal syndication; advertised in every page head |
| IndexNow key | `/<key>.txt` | `public/9f4c2a7d8e1b6c3f5a0d9e7b2c4f8a16.txt` | Proves ownership for IndexNow |
| Manifest | `/site.webmanifest` | `public/site.webmanifest` | Installable app metadata and shortcuts |
| Social card | `/media/brand/og-card.jpg` | `npm run generate:assets` | Open Graph and Twitter previews |

Every page also carries:

- A unique title, description, canonical URL, Open Graph and Twitter card.
- `Person`, `WebSite`, `Organization`, and `ProfessionalService` JSON-LD.
- `ProfilePage` on `/about`, `BlogPosting` on articles, `FAQPage` on `/faq`
  and `/global`, `ItemList` on `/projects` and `/global`, `Service` on
  `/services`, `ContactPage` on `/contact`, and breadcrumbs on key pages.
- `hreflang`-free English content (`lang="en"`), `geo.position`, and Lagos
  place metadata.
- An RSS `<link rel="alternate">` in the document head.

`/writings` intentionally sets `robots: noindex, follow` and canonicals to
`/blog`, so the legacy URL cannot compete with the journal.

### The one source of truth

All facts come from `lib/profile.ts`. `lib/seo-config.ts` turns them into
metadata and JSON-LD; `lib/global.ts` holds the tech-hub corridors;
`lib/faq.ts` holds the answers used by both the visible page and the markup.
Change a fact once and rebuild — do not edit the generated files in `out/`.

### Refresh the "last updated" date

When the profile changes materially:

1. Update `CONTENT_UPDATED` in `lib/seo-config.ts` (currently `2026-11-06`).
2. Rebuild. The sitemap `lastModified`, `llms.txt`, `llms-full.txt`, and
   `ProfilePage` date follow automatically.

## 2. Verify the build locally

```bash
npm run type-check
npm run build
node scripts/preview-server.cjs
```

Then check:

```bash
curl -s http://localhost:4173/robots.txt
curl -s http://localhost:4173/sitemap.xml | head -40
curl -s http://localhost:4173/llms.txt | head -40
curl -s http://localhost:4173/llms-full.txt | head -40
curl -s http://localhost:4173/feed.xml | head -25
```

Confirm `out/` contains `llms.txt`, `llms-full.txt`, `feed.xml`, `sitemap.xml`,
`robots.txt`, and the IndexNow key file. If a dotted route ever fails to export,
the fallback is a static file in `public/` with the same name; keep the URL
stable either way.

Validate the markup:

- [Schema Markup Validator](https://validator.schema.org/)
- [Google Rich Results Test](https://search.google.com/test/rich-results)
- [PageSpeed Insights](https://pagespeed.web.dev/)

Paste the live URL, not the local one. A page can be valid and still show no
rich result; eligibility is not a guarantee.

## 3. After every deploy

1. Open `https://mriridescent.africa/robots.txt` and confirm the sitemap line.
2. Open `https://mriridescent.africa/sitemap.xml` and confirm `/global` and
   `/faq` are present.
3. Open `https://mriridescent.africa/llms.txt` and `llms-full.txt` — they should
   be plain text, not HTML.
4. Open `https://mriridescent.africa/feed.xml` — it should be valid RSS.
5. Submit the sitemap in Google Search Console and Bing Webmaster Tools.
6. Run IndexNow (below).
7. Request indexing for the pages that changed.

### IndexNow

```bash
npm run seo:indexnow -- --dry-run   # inspect the payload
npm run seo:indexnow                # submit every sitemap URL
```

This works only after the site is live, because the script fetches the deployed
sitemap and the key file. It notifies Bing, Yandex, Seznam, Naver, and Yep. It
does **not** submit to Google; Google uses the sitemap and Search Console.

If you rotate the key, change all three in step: `public/<key>.txt`,
`INDEXNOW_KEY` in `.env.example`/Netlify, and the default in
`scripts/seo-indexnow.mjs`. Then submit again.

## 4. Search engines — the owner-only steps

These require accounts and cannot be done from the repository.

### Google Search Console

1. Go to [search.google.com/search-console](https://search.google.com/search-console).
2. Add a **Domain** property for `mriridescent.africa` and verify by DNS. This
   covers every subdomain and protocol.
3. Alternative: add a **URL prefix** property and use the HTML tag. If you use
   the tag, paste only the token into `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`,
   then rebuild and redeploy.
4. Submit `https://mriridescent.africa/sitemap.xml`.
5. Use **URL Inspection → Request indexing** for `/`, `/global`, `/faq`,
   `/about`, `/services`, `/projects`, and each new journal post.
6. Check **Pages** after 48–72 hours for excluded URLs and fix real problems.

### Bing Webmaster Tools

1. Go to [bing.com/webmasters](https://www.bing.com/webmasters).
2. Import the site from Google Search Console (fastest) or verify by DNS/tag.
3. If using a tag, set `NEXT_PUBLIC_BING_SITE_VERIFICATION` and rebuild.
4. Submit the sitemap. Bing also powers DuckDuckGo and some ChatGPT search
   surfaces, so this matters more than its market share suggests.

### Other engines

| Engine | Where | Notes |
| --- | --- | --- |
| Yandex | [webmaster.yandex.com](https://webmaster.yandex.com) | Verify, submit sitemap; IndexNow also notifies it |
| Baidu | [ziyuan.baidu.com](https://ziyuan.baidu.com) | Optional; useful for China-facing work |
| Naver | [searchadvisor.naver.com](https://searchadvisor.naver.com) | Covered partly by IndexNow |
| Seznam | [search.seznam.cz](https://search.seznam.cz) | Covered partly by IndexNow |

### Verification variables

Both are optional and read at build time:

```dotenv
NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION=
NEXT_PUBLIC_BING_SITE_VERIFICATION=
```

Use the token only, not the whole `<meta>` tag. DNS verification is preferable
because it survives redesigns and does not bake a token into the bundle.

## 5. AI answer engines (GEO)

GEO here means **Generative Engine Optimization**: making the site easy to quote
accurately, not tricking a model.

What is already in place:

- `llms.txt` and `llms-full.txt` state the canonical facts, dates, and links.
- `robots.txt` explicitly allows GPTBot, OAI-SearchBot, ChatGPT-User,
  ClaudeBot, Claude-User, Claude-SearchBot, PerplexityBot, Google-Extended,
  Applebot-Extended, CCBot, Meta-ExternalAgent, cohere-ai, YouBot,
  DuckAssistBot, Diffbot, and Amazonbot.
- JSON-LD gives every claim a machine-readable home.
- The FAQ page answers the questions people actually type, in plain language.
- The global page lists 100+ tech hubs with an explicit "not offices" caveat,
  which reduces the risk of a model inventing a physical presence.

What the owner can do:

1. Keep the same one-paragraph bio everywhere: site, LinkedIn, GitHub, ORCID,
   Crunchbase, Medium, conference bios. Models learn entities from agreement.
2. Put the email `me@mriridescent.africa` in every profile. It is the strongest
   cross-platform identifier after the name.
3. Publish original explanations, not reposts. Answer engines cite the source
   that explains, not the account that shares.
4. After publishing, ask an assistant a real question (for example, "Who is a
   Lagos-based growth partner for African brands entering Europe?") and see
   whether the site is cited. Record the result monthly. Do not optimize for a
   single prompt.
5. Never fabricate credentials, clients, or offices for a model to repeat. A
   wrong claim propagates further than a missing one.

There is no paid submission to ChatGPT, Claude, Perplexity, or Google AI
Overviews. Anyone selling "AI SEO guaranteed placement" is selling noise.

## 6. Profiles, directories, and tech hubs

The goal is not to spray the same bio across 500 link farms. It is to be
present, consistent, and useful in the places that already have the audience.

### Tier 1 — claim and keep current

| Platform | Why | Action |
| --- | --- | --- |
| [GitHub](https://github.com/MrIridescent) | Proof of work, already linked | Pin the six best repositories; keep the profile README current |
| [LinkedIn](https://www.linkedin.com/in/mriridescent) | Primary professional search surface | Headline matches the site; featured links to `/services` and `/case-studies` |
| [ORCID](https://orcid.org/0000-0002-6340-2782) | Persistent researcher ID | Add works, education, and the site URL |
| [Crunchbase](https://www.crunchbase.com/) | Company and founder entity | Create/claim Iridescent Internet Solutions; link the site |
| [Wellfound](https://wellfound.com/) | Startup hiring and founder discovery | Founder profile with the same positioning |
| [Product Hunt](https://www.producthunt.com/) | Launch surface | Use only when a real product launches |
| [Medium](https://medium.com/@iammriridescent) | Canonical republishing | Republish with a canonical link back to `/blog` |
| [dev.to](https://dev.to/) / [Hashnode](https://hashnode.com/) | Developer discovery | Technical posts with canonical URLs |
| [Behance](https://www.behance.net/) / [Dribbble](https://dribbble.com/) | Creative direction and film | Only work you can show publicly |
| [Linktree](https://linktr.ee/mriridescent_) | Social bio link | Point to the site, not to a competing landing page |

Rules: same name, same role line, same email, same location framing ("Lagos,
Nigeria · remote worldwide"). Do not claim an office, employee count, or client
you cannot evidence.

### Tier 2 — ecosystems and communities

Being *seen* in tech hubs is mostly participation, not a directory listing.

- **Lagos / Nigeria:** Lagos Startup Week, Techpoint Africa, Nigerian Startup
  Ecosystem (NSE), Co-Creation Hub (CcHub), Yaba ecosystem meetups, FEPAR.africa
  programmes.
- **Africa:** AfriLabs, Lagos/Nairobi/Kigali/Cape Town startup weeks, Africa Tech
  Festival, Afrobytes, DEMO Africa.
- **Europe:** London Tech Week, Slush (Helsinki), Web Summit (Lisbon), Tech Open
  Air (Berlin), VivaTech (Paris). Apply to speak or attend; do not buy a badge and
  call it presence.
- **North America:** Y Combinator Startup School, On Deck, local founder dinners,
  SXSW, TechCrunch Disrupt.
- **Middle East:** GITEX (Dubai), LEAP (Riyadh).
- **Asia-Pacific:** Tech in Asia (Singapore/Jakarta), Rise (Hong Kong), SusHi
  Tech (Tokyo).
- **Latin America:** Web Summit Rio, Startup Chile networks.

For each: one useful contribution (a talk, a workshop, a written teardown, a
mentorship slot) beats ten profile links. After the event, publish a short note
on `/blog` and link it from the event's community thread.

### Tier 3 — citations and digital PR

- Podcasts and newsletters aimed at founders, marketers, and engineers.
- Guest essays with a byline and a link to a relevant page, not always the home
  page.
- Open-source releases with a clear README and the site in the profile.
- Conference speaker bios that use the same paragraph as `llms.txt`.
- Journalist requests (Qwoted, Featured, SourceBottle) only when the topic is
  genuinely yours.

Skip: paid link networks, "SEO guest post" mills, PBNs, comment spam, and
directories that exist only to sell links. They create risk, not visibility.

## 7. Content cadence

Search visibility compounds through pages that answer real questions. A
sustainable cadence:

| Cadence | Output | Example |
| --- | --- | --- |
| Monthly | One journal essay | "What a growth audit actually finds" |
| Quarterly | One case study | "How a Lagos fintech entered the UK market" |
| Per project | One repository README + one short note | A shipped open-source tool |
| Per event | One recap with the argument, not the diary | A conference talk write-up |
| Twice a year | One substantial guide | "Market entry in Nigeria: a technical founder's map" |

Each piece should:

1. Answer a question someone actually asks.
2. Link to one relevant service or case-study page with descriptive anchor text.
3. End with a clear next step (email or `/contact`).
4. Be republished with a canonical link if it goes to Medium/dev.to.

Do not publish the same city page 100 times to chase "growth hacker in <city>".
That is a doorway pattern and can suppress the whole site. The `/global` page
handles geography honestly in one place.

## 8. Measure what matters

Track monthly in a simple sheet:

| Metric | Source | Why |
| --- | --- | --- |
| Indexed pages | Google Search Console → Pages | Confirms new routes are discoverable |
| Impressions and clicks | GSC → Performance | Whether titles and descriptions earn the click |
| Queries containing the name | GSC → Performance | Branded demand is the strongest signal |
| Top landing pages | GSC / analytics | Which offers attract search demand |
| Referring domains | GSC → Links, Bing, Ahrefs (optional) | Earned links, not bought ones |
| AI citations | Manual prompt checks | Whether `llms.txt` and the pages are being used |
| Contact enquiries | Resend / inbox | The only metric that pays |

Set a 90-day review. SEO changes rarely show in week one. If impressions rise
but clicks do not, rewrite titles and descriptions. If clicks rise but enquiries
do not, fix the offer and the call to action, not the keywords.

## 9. Guardrails

- **One entity, one story.** Name, role, location, and email must agree across
  every profile. Contradictions confuse both search engines and people.
- **No invented offices.** The global page lists collaboration corridors. Never
  describe them as offices or imply staff in those cities.
- **No fake credentials or clients.** The Zandbox and Helpman engagements have
  ended; say so. A smaller true record outranks a larger false one.
- **No doorway pages.** One strong `/global` page, not 100 thin city pages.
- **No keyword stuffing.** Keywords belong in titles, descriptions, headings,
  and body copy where they read naturally. The `keywords` meta tag is a weak
  signal; the visible page is not.
- **No purchased links or reviews.**
- **No guarantee language.** Do not promise "page one", "AI citation", or
  "guaranteed leads" to clients or to yourself.

## 10. Acceptance checklist

After the next production deploy:

- [ ] `https://mriridescent.africa/sitemap.xml` includes `/global` and `/faq`.
- [ ] `robots.txt` points to the sitemap and allows AI crawlers.
- [ ] `llms.txt` and `llms-full.txt` serve plain text and contain the current
      email.
- [ ] `feed.xml` validates and lists the five local essays.
- [ ] The IndexNow key file is live and matches the script.
- [ ] Google Search Console and Bing Webmaster Tools are verified.
- [ ] The sitemap is submitted in both.
- [ ] `npm run seo:indexnow` returns HTTP 200 or 202.
- [ ] Rich Results Test finds valid `Person`, `Organization`, `WebSite`, and
      `FAQPage` markup on the relevant pages.
- [ ] `/writings` is `noindex` and canonicalises to `/blog`.
- [ ] GitHub, LinkedIn, ORCID, Crunchbase, and Linktree carry the same role line
      and email.
- [ ] `CONTENT_UPDATED` reflects the latest material change.

Technical work is done when the checklist passes. Visibility is then a
compounding function of original work, consistent identity, and time.
