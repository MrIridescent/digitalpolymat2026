## 2. Path A — Create the new Netlify site with Git integration

### 2.1 Create or sign in to the new Netlify account

1. Go to <https://app.netlify.com>.
2. If you are signed into the old account, sign out first. Confirm the team/account name in the top-left menu is the **new** one, not `mriridescent-polymaticcoder`.
3. Choose **Sign up** → **GitHub**, or sign in with GitHub.
4. Authorize Netlify to access the GitHub account if prompted.

> The account must have available build minutes/credits. Nothing in this repository depends on a specific Netlify account.

### 2.2 Import the repository

1. On the Netlify dashboard, choose **Add new site** → **Import an existing project**.
2. Choose **Deploy with GitHub**.
3. If GitHub asks, authorize the Netlify GitHub App for the `MrIridescent` account.
4. In the repository list, choose `digitalpolymat2026` (owner `MrIridescent`).
5. If the repository is not listed, choose **Configure the Netlify app on GitHub** and grant access to that repository, then return to Netlify and refresh.
6. Select branch **`main`**.

### 2.3 Confirm the build settings

Netlify reads `netlify.toml`, so most fields fill in automatically. Confirm:

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Publish directory | `out` |
| Functions directory | `netlify/functions` (may be read from `netlify.toml`; leave as detected) |
| Node version | `20` (from `netlify.toml`; do not override in the UI) |

If the UI shows different values, replace them with the table above. The build must publish `out`, because `next.config` uses `output: 'export'`.

### 2.4 Do not install the Next.js runtime plugin

This is a **static export**, not a server-rendered Next.js app.

1. During import, if Netlify offers to add the **Next.js runtime** or `@netlify/plugin-nextjs`, decline or remove it.
2. After the site exists, open **Site configuration → Build & deploy → Build plugins** and confirm the list is empty.
3. If `@netlify/plugin-nextjs` is present, remove it.
4. Do not add any `[[plugins]]` block to `netlify.toml`.

Why: the Next.js runtime expects a server build and can override the publish directory or add serverless routing this project does not use. The site is complete static HTML plus one hand-written Netlify Function.

### 2.5 Create the site

1. Expand **Environment variables** if the import screen offers it. You can add variables now or after the first deploy; section 3 covers the exact values.
2. Choose **Deploy site**.
3. Wait for the first build. A healthy log ends with a published deploy and a URL like `https://<random-name>.netlify.app`.
4. Open the deploy URL. The homepage should render; the journal should show the five local essays.

If the first build succeeds but the site is blank or 404s, check the publish directory is exactly `out` and that no Next.js plugin is installed.

### 2.6 Name the site

1. Open **Site configuration → General → Site details**.
2. Choose **Change site name**.
3. Use a clear name such as `mriridescent` (or your preferred available name).
4. Save. The temporary URL becomes `https://<name>.netlify.app`.

Record the site name and site ID (same page) in your tracking note.

## 3. Add environment variables in Netlify

These variables are read in two places: at **build time** for the static export, and at **function runtime** for contact delivery. Add them all in Netlify, not in GitHub.

### 3.1 Required values

| Variable | Value | Where it is used |
| --- | --- | --- |
| `RESEND_API_KEY` | The **new** Resend key (see section 5) | Contact function runtime |
| `CONTACT_TO_EMAIL` | `me@mriridescent.africa` | Contact function runtime |
| `CONTACT_FROM_EMAIL` | `David Akpoviroro Oke <website@hello.i2sltd.click>` | Contact function runtime |
| `CONTACT_AUTO_REPLY` | `true` | Contact function runtime |
| `NEXT_PUBLIC_SITE_URL` | `https://mriridescent.africa` | Build-time canonical URLs, metadata, sitemap |

Notes:

- `NEXT_PUBLIC_SITE_URL` has no trailing slash. It is public by design (the `NEXT_PUBLIC_` prefix only means it is embedded in the client bundle). Do not put any secret in a `NEXT_PUBLIC_` variable.
- `CONTACT_TO_EMAIL` and `CONTACT_FROM_EMAIL` have the same defaults in code, but set them explicitly so the deployed behaviour is visible and intentional.
- `RESEND_API_KEY` is a secret. Never commit it and never paste it into chat.

### 3.2 Add each variable (exact clicks)

1. Open the site in Netlify.
2. Go to **Site configuration** (sometimes labelled **Project configuration** in newer UI).
3. Choose **Environment variables**.
4. Choose **Add a variable** → **Add a single variable**.
5. Enter the **Key** exactly as shown in the table.
6. Enter the **Value** exactly. Preserve the angle brackets and spaces in `CONTACT_FROM_EMAIL`.
7. Under **Scopes**, select **All deploy contexts** (or at minimum both **Builds** and **Functions**).
8. For `RESEND_API_KEY`, mark it as containing a secret value if that option is shown.
9. Choose **Create variable** / **Save**.
10. Repeat for all five variables.

### 3.3 Alternative: import a local `.env` file

Netlify allows importing variables from a `.env` file. This is faster but easier to get wrong.

1. Create the file locally, never inside the repository, for example in your home directory.
2. Include only the five production variables.
3. In **Environment variables**, choose **Import from a .env file** and upload it.
4. Review each imported value and its scopes before saving.
5. Delete the temporary file after import.
6. Confirm `.env` and `.env.local` are still ignored by Git: `.gitignore` contains both.

Do not import `CONTENTFUL_MANAGEMENT_TOKEN`, any preview token, or any local-only value.

### 3.4 Apply the variables

Static exports bake environment values at build time.

1. Go to **Deploys**.
2. Choose **Trigger deploy** → **Clear cache and deploy site**.
3. Wait for the new deploy to finish.
4. Open the site and view the page source; confirm the canonical URL uses `https://mriridescent.africa`.

Changing an environment variable later requires another deploy before it affects the static HTML. Function-only variables such as `RESEND_API_KEY` take effect for new invocations, but redeploying keeps everything consistent.

### 3.5 Contentful (optional, currently blank)

Leave these unset for now. The journal uses the five local essays until valid credentials exist.

When you are ready to enable Contentful, add:

| Variable | Value |
| --- | --- |
| `CONTENTFUL_SPACE_ID` | Your space ID |
| `CONTENTFUL_ACCESS_TOKEN` | Delivery API token (published content) |
| `CONTENTFUL_ENVIRONMENT` | `master` |
| `CONTENTFUL_CONTENT_TYPE` | `blogPost` |
| `CONTENTFUL_LOCALE` | `en-US` |
| `CONTENTFUL_USE_PREVIEW` | `false` |

Then trigger a new deploy.

Rules:

- Production must use the **Delivery API** and `CONTENTFUL_USE_PREVIEW=false`.
- A static export bakes whatever it reads. Enabling preview on Netlify would publish drafts.
- `CONTENTFUL_PREVIEW_ACCESS_TOKEN` belongs in local `.env.local` only, alongside `CONTENTFUL_USE_PREVIEW=true`, for local draft previews.
- `CONTENTFUL_MANAGEMENT_TOKEN` is for local publishing only. Never add it to Netlify.
- Content changes in Contentful are not live until the site rebuilds. Use a deploy hook or trigger a deploy after publishing.

## 4. Attach `mriridescent.africa`

Do this after the first successful deploy. DNS changes can take minutes to propagate; TLS is provisioned automatically once DNS points at Netlify.

### 4.1 Add the domain in Netlify

1. Open the site.
2. Go to **Domain management** (or **Domain configuration**).
3. Choose **Add a domain**.
4. Enter `mriridescent.africa`.
5. Choose **Verify** / **Add domain**.
6. Netlify now shows the DNS records or nameservers it needs. Use exactly what Netlify displays; do not copy stale values from another guide.

### 4.2 Option A — Use Netlify DNS (simplest)

1. In Netlify, choose **Set up Netlify DNS** for the domain.
2. Netlify shows four nameservers.
3. At your registrar, replace the domain's nameservers with those four.
4. Save at the registrar.
5. Return to Netlify and choose **Verify DNS configuration**.
6. Wait for propagation; Netlify shows the domain as active when it resolves.

### 4.3 Option B — Keep DNS at your current provider

1. In Netlify, choose the option to manage DNS externally.
2. At your DNS provider, add the records Netlify displays. Typically:
   - An apex record for `mriridescent.africa` using the ALIAS/ANAME value Netlify gives, or the A record IP Netlify shows.
   - A `CNAME` for `www` pointing to the Netlify site hostname Netlify shows.
3. Do not guess IP addresses or hostnames; use the values on Netlify's domain page.
4. Remove conflicting old A/CNAME records for the same hostnames.
5. Return to Netlify and verify.

### 4.4 Enable HTTPS

1. Once the domain is active, open **Domain management → HTTPS**.
2. Wait for the Let's Encrypt certificate to be issued (usually automatic).
3. Enable **Force HTTPS**.
4. Open `https://mriridescent.africa` and confirm the padlock and certificate.

### 4.5 Rebuild for the final canonical URL

If the first deploy happened before the domain or before `NEXT_PUBLIC_SITE_URL` was set:

1. Go to **Deploys**.
2. Choose **Trigger deploy** → **Clear cache and deploy site**.
3. Confirm the page source canonical link is `https://mriridescent.africa/...`.
4. Confirm `https://mriridescent.africa/sitemap.xml` and `robots.txt` load.

## 6. Path B — Deploy through GitHub Actions (optional)

Use this only if you are not using Netlify Git integration, or if you need a manual fallback.

The workflow is `.github/workflows/deploy-netlify.yml`. It runs only on `workflow_dispatch`, builds with `npx netlify-cli@latest deploy --build --prod`, and deploys functions from `netlify/functions`.

### 6.1 Create a Netlify personal access token

1. Netlify → click your avatar → **User settings**.
2. Open **Applications** → **Personal access tokens**.
3. Choose **New access token**.
4. Name it `digitalpolymat2026-github-actions`.
5. Set an expiry you will remember.
6. Generate and copy the token once.

### 6.2 Find the site ID

1. Netlify → open the new site.
2. **Site configuration → General → Site details**.
3. Copy the **Site ID** (a UUID). This is not the site name and not the deploy URL.

Do not reuse the site ID from the old local `.netlify/state.json`; that belongs to the depleted account. `.netlify/` is gitignored, so it is not in the repository.

### 6.3 Add the GitHub secrets — UI

1. Open `https://github.com/MrIridescent/digitalpolymat2026`.
2. Choose **Settings**.
3. In the left sidebar, choose **Secrets and variables** → **Actions**.
4. Choose **New repository secret**.
5. Name: `NETLIFY_AUTH_TOKEN`; Secret: paste the token; choose **Add secret**.
6. Choose **New repository secret** again.
7. Name: `NETLIFY_SITE_ID`; Secret: paste the site ID; choose **Add secret**.

Both names must match the workflow exactly. They are repository secrets, not environment secrets.

### 6.4 Add the GitHub secrets — terminal alternative

Run these from the repository. The CLI prompts for each value without echoing it:

```bash
gh secret set NETLIFY_AUTH_TOKEN -R MrIridescent/digitalpolymat2026
gh secret set NETLIFY_SITE_ID -R MrIridescent/digitalpolymat2026
```

Verify only the names are listed (values are never shown):

```bash
gh secret list -R MrIridescent/digitalpolymat2026
```

### 6.5 Trigger the deploy

UI:

1. Open the repository's **Actions** tab.
2. Select **Deploy to Netlify** in the left sidebar.
3. Choose **Run workflow**.
4. Branch: `main`.
5. Choose **Run workflow**.

Terminal:

```bash
gh workflow run deploy-netlify.yml -R MrIridescent/digitalpolymat2026 --ref main
gh run list -R MrIridescent/digitalpolymat2026 --workflow deploy-netlify.yml --limit 1
gh run watch <run-id> -R MrIridescent/digitalpolymat2026 --exit-status
```

A successful run ends with a Netlify production deploy URL. Open it and continue to section 7.

### 6.6 What the workflow does not do

- It does not set Netlify site environment variables. Those still belong in Netlify (section 3).
- It does not install `@netlify/plugin-nextjs`.
- It does not trigger on push; dispatch it manually.
- It deploys the commit it checks out, so make sure `main` is the commit you intend.

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Build fails: `Cannot find module 'autoprefixer'` | Dev dependencies skipped | Confirm `NPM_FLAGS=--include=dev` in `netlify.toml`; clear cache and redeploy. Node must be 20. |
| Build succeeds, site shows 404 | Publish directory is wrong | Set publish to `out`; remove the Next.js runtime plugin. |
| Build tries to start a server or expects `.next` | Next.js runtime plugin installed | Remove `@netlify/plugin-nextjs` from Build plugins; keep `output: 'export'`. |
| Contact form returns 500 | `RESEND_API_KEY` missing or wrong scope | Add the key to Environment variables with the Functions scope; redeploy. |
| Contact form returns 404 | Redirect or functions directory missing | Confirm `netlify.toml` has the `/api/contact` redirect and `netlify/functions` is deployed. |
| Resend rejects the from address | Domain not verified | Verify `hello.i2sltd.click` in Resend; use an address on that domain. |
| Email goes to spam | SPF/DKIM/DMARC incomplete | Complete Resend's DNS records and allow propagation. |
| Canonical links still use a Netlify preview URL | `NEXT_PUBLIC_SITE_URL` not set at build time | Set it in Netlify, clear cache, redeploy. |
| New quote or Contentful post not visible | Static export is baked | Trigger a new deploy. Content changes need a rebuild. |
| GitHub Action fails: not authorized | Bad token or wrong site ID | Recreate the token, confirm the site ID, update both secrets. |
| GitHub Action deploys the old account's site | Stale site ID | Use the new site's ID; never copy the old `.netlify/state.json` value. |
| Duplicate deploys | Git integration and GitHub Action both enabled | Choose one route and disable the other. |
| Domain stuck on "Awaiting DNS" | Records not saved or conflicting | Recheck the exact records Netlify shows; remove conflicting A/CNAME entries; wait for propagation. |

## 9. Security rules

- Never commit `.env`, `.env.local`, or any key. Both are gitignored; keep it that way.
- Never put `RESEND_API_KEY` or `CONTENTFUL_MANAGEMENT_TOKEN` in a `NEXT_PUBLIC_` variable.
- The Resend key shared in chat is compromised; rotate it and revoke the old one (section 5).
- Keep the old Netlify account and its site untouched.
- Prefer Netlify's environment-variable UI or a temporary local `.env` import over pasting secrets into chat or issue trackers.
- GitHub secret values are write-only; verify only their names with `gh secret list`.
- Use a dedicated Netlify token with an expiry, and revoke it when no longer needed.
- If a secret is ever exposed, rotate it first, then clean up history if necessary. Do not rely on deleting a commit alone.
